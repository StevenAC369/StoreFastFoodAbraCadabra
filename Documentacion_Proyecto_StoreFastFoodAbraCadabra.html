1. Qué es el proyecto

StoreFastFoodAbraCadabra es una aplicación de escritorio para un restaurante de comida rápida. La versión actual permite iniciar sesión y administrar el catálogo de productos desde la pantalla principal. El resto de las pestañas presenta partes de una interfaz en construcción.

Inicio de la aplicación → acceso → catálogo de productos → PostgreSQL

Disponible y conectado

  • Validación del usuario y contraseña.
  • Lectura y filtrado del catálogo.
  • Alta de productos.
  • Eliminación de productos seleccionados.
  • Apertura de la ventana de ajustes.

Interfaz todavía parcial

  • Tomar pedidos y calcular el total.
  • Cola de cocina e historial.
  • Reportes y métricas.
  • Gestión de clientes desde la interfaz.
  • Gestión real de miembros, roles y permisos.

Responsabilidades y llamadas

Las ventanas capturan la interacción. Las clases de Servicios adaptan esa interacción (por ejemplo, construyen el modelo de la tabla) y llaman a los DAO. Las clases de Data ejecutan SQL con PreparedStatement y traducen los resultados a entidades. Conexion centraliza la apertura de conexiones JDBC.

Vista Swing → Servicios → DAO (JDBC) → PostgreSQL

Clases principales de la interfaz

  • Main: punto de entrada alternativo; abre la ventana de acceso Master.
  • Master: formulario de acceso y navegación a Inicio tras validar las credenciales.
  • Inicio: panel con pestañas de resumen, nuevo pedido, cocina, historial, reportes y bodega/logística.
  • AgregarProducto: diálogo modal con campos del catálogo.
  • UsuarioActivo: conserva en memoria el nombre de la sesión actual; no es persistencia.

Los archivos .form de NetBeans describen el diseño visual. El bloque generado de Swing se marca como código generado; los cambios de comportamiento suelen ir en los manejadores de eventos y servicios.

3. Requisitos y puesta en marcha

Antes de ejecutar

  1. Usar un JDK compatible con la configuración del proyecto (el pom.xml declara Java 26) y Maven.
  2. Configurar acceso a una instancia PostgreSQL autorizada y disponible desde el equipo.
  3. Revisar Data.Conexion: la URL, el usuario y la contraseña están configurados dentro del código actual. No distribuir ni publicar esos valores; reemplazarlos por configuración local segura antes de compartir el proyecto.
  4. Comprobar que el usuario de base de datos tenga permisos para conectarse, consultar y crear las tablas usadas por la aplicación.
Importante para el equipo: la configuración de conexión debe externalizarse antes de desplegar o compartir el repositorio. Este documento intencionalmente no reproduce host, usuario ni contraseña.

Arranque desde el IDE

  1. Abrir el proyecto Maven en el IDE.
  2. Resolver la dependencia JDBC PostgreSQL definida en pom.xml.
  3. Ejecutar la clase projects.abracadabra.mavenproject2.Vista.Main (método main). Como alternativa, Master también tiene un punto de entrada.
  4. Si aparece un error de conexión, verificar primero la red, el servidor y la configuración local antes de diagnosticar la interfaz.

Nota de configuración de Maven

La propiedad exec.mainClass en el pom.xml apunta al punto de entrada projects.abracadabra.mavenproject2.Vista.Main. La clase Vista.Master también tiene un método main.

Inicialización de tablas

Los DAO crean sus tablas con CREATE TABLE IF NOT EXISTS al inicializarse. Por eso, el acceso a la base de datos es necesario desde el inicio de sesión y al cargar el panel; las tablas no se crean si no hay conexión.

Primera comprobación: ejecutar la aplicación desde el IDE con la configuración local, iniciar sesión y confirmar que aparece el panel principal y que la tabla de productos carga datos o queda vacía sin error.

4. Guía de las acciones operativas

Acceso

  1. Escribir el usuario y la contraseña en la ventana inicial.
  2. Pulsar Iniciar.
  3. Con credenciales válidas, se abre el panel principal. Si no son válidas, aparece un mensaje de error. Si PostgreSQL no responde, se informa un error de conexión.

Ver y filtrar productos

Abrir la pestaña Nuevo Pedido. La tabla se carga al construir la pantalla. En la columna de texto Buscar, escribir el código o la descripción para actualizar los resultados. La búsqueda se dispara al presionar teclas; no hay un botón de búsqueda separado.

AcciónResultado
TodosRecarga la lista completa.
HamburgueasFiltra por categoría «Hamburguesas».
AcompañamientosFiltra esa categoría.
BebidasFiltra esa categoría.
PostresFiltra esa categoría.

La búsqueda del campo de texto compara el valor capturado contra código y descripción. Los filtros de categoría dependen de que el texto guardado en la base coincida con el nombre que espera cada filtro.

Agregar un producto

  1. Pulsar Agregar en la pantalla de catálogo.
  2. Completar código, descripción, precio, cantidad, estado y categoría.
  3. El precio debe poder convertirse a número decimal y la cantidad a entero. Los estados ofrecidos son «Crudo», «Cocinado» y «Para Enviar»; las categorías incluyen «Hamburguesas», «Bebidas», «Acompañamientos», «Combos» y «Postres».
  4. Pulsar Agregar dentro del diálogo. Al finalizar, cerrar el diálogo para que el panel recargue la tabla.
Atención: el botón «Cancelar» del diálogo no tiene un manejador conectado. Para cerrar el diálogo, usar el control de cierre de la ventana. El formulario no valida que todos los campos tengan contenido; revisar los datos antes de guardar.

Eliminar un producto

  1. Seleccionar una fila de la tabla.
  2. Pulsar Eliminar.
  3. La fila se borra por su código y la tabla se vuelve a cargar. Sin fila seleccionada no se envía una eliminación.

6. Datos y flujo interno

Tablas que administra el código

TablaCampos principalesUso observado
usuariosusername (clave), password, rolAutenticación de acceso en UserDAO.
productoscodigo (clave), descripcion, precio, cantidad, estado, categoriaListado, búsqueda, inserción y eliminación desde el catálogo.
clientesidentificacion (clave), nombres, telefono, direccionDAO y métodos de servicio disponibles; sin controles de interfaz conectados.

Flujo de productos

  • Inicio llama a ServiciosProductos.CargarTabla al abrirse.
  • ServiciosProductos llama a ProductosDAO y proyecta las entidades en una JTable.
  • ProductosDAO ejecuta las operaciones de PostgreSQL usando parámetros para los valores de consulta.
  • El código de producto es la clave primaria; códigos duplicados no pueden guardarse como registros separados.

Flujo de clientes y usuarios

ServiciosCliente y ClienteDAO cubren cargar, agregar, eliminar y buscar clientes, además de actualizar en el DAO. Sin embargo, no existe una pantalla conectada a esos métodos desde el botón «Administrar Clientes». ServiciosUsuario delega la autenticación en UserDAO; no hay un flujo de interfaz completo para administrar usuarios.

7. Cómo continuar el desarrollo

Convenciones que ya usa el código

  • Mantener separadas vista, servicio, DAO y entidad.
  • Usar PreparedStatement para valores variables de SQL.
  • Al agregar una acción nueva, conectar su manejador de evento, servicio, DAO y actualización visual; comprobar tanto éxito como error.
  • En formularios, validar campos vacíos y formatos antes de llamar al DAO; mostrar mensajes que ayuden a corregir los datos.
  • Para operaciones destructivas, seleccionar el registro correcto y actualizar la tabla después de la operación.

Orden sugerido para una persona nueva

  1. Revisar primero la vista Master y seguir el evento de acceso hasta ServiciosUsuario y UserDAO.
  2. Seguir el ciclo completo de productos: Inicio → ServiciosProductos → ProductosDAO → entidad Producto.
  3. Ejecutar la aplicación con una base de desarrollo autorizada y probar recarga, filtros, alta y eliminación.
  4. Antes de implementar clientes, conectar explícitamente la interfaz con ServiciosCliente y decidir el flujo de pantalla.
  5. Tratar pedidos, cocina, historial, reportes y logística como trabajo pendiente; actualmente no existe persistencia funcional para esos flujos.
Antes de compartir o desplegar: sacar las credenciales de Data.Conexion, revisar la configuración del punto de entrada Maven y sustituir las credenciales de demostración/autenticación por un mecanismo apropiado para el entorno. No incluir secretos en capturas, manuales ni repositorios.

Estado resumido

La aplicación es una base funcional para acceso y mantenimiento elemental del catálogo. Los formularios de pedidos, cocina, clientes, reportes, usuarios y ajustes aún requieren conexión de eventos y operaciones de negocio antes de presentarse como funciones disponibles para el personal del restaurante.

Bienvenido/a al proyecto.
Para empezar con seguridad: configura una base local, ejecuta Vista.Main y prueba únicamente las acciones marcadas como operativas en esta guía.
